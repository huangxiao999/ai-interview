## 2. 实施范围及业务归属

M-06 的 `knowledge` 包负责公共技术知识的创建、追加不可变版本、人工批准/拒绝、原操作查询及精确版本来源读取。M-01继续负责身份/角色/凭证代次；M-02删除资格和私有资料规则未被新模块重写。

实际闭环：维护者登录 → 维护页填写标题、原文、来源及条件 → 提交待审版本 → 核对固定版本全文/摘要/来源/条件 → 明确批准或拒绝并填写理由 → 查询原操作/审核事实 → 追加V2并回看V1。提交者可审核自己的版本，符合原首期不强加双人复核的设计；没有自动批准或默认勾选批准。

本项无模型/embedding、网络抓取、索引、向量、私有候选、文件上传、后台调度或租约。公共知识不关联任何用户简历/JD根，不新增私有副本，因此不扩展当前私有清理类型；维护者仍不能读用户私有资料。后续新增私有查询、候选或配置绑定时必须按设计第8节同步接入删除屏障与完整清单，不能将本项“不新增私有数据”沿用到后续任务。

## 3. 固定输入、幂等与事务

### 3.1 输入保护与来源边界

所有文本必填，CRLF/CR统一为LF并去首尾空白，拒绝空值/NUL/超限，不截断。上限按Unicode码点：标题200、正文100000、URL2048、来源定位1000、技术版本/适用条件4000、许可范围说明2000、人工核实说明2000、审核理由2000；另需人工核实日期。这是一次人工粘贴的工程资源保护值，不套用简历/JD限额，也不代表已测最大并发或知识覆盖。

摘要v1按标题、原文、URL、锚点、适用条件、许可说明、核实说明、ISO日期的固定顺序计算，各字段UTF-8字节前加四字节长度，再计算SHA-256。契约随不可变V7及代码绑定；后续不能无版本地改摘要规则。

来源URL仅允许有主机、无用户名密码的HTTP/HTTPS。应用不访问来源、不运行其中的指令，格式合法不证明真实来源、许可或技术结论正确。页面纯文本展示，来源链接协议再次校验；合成 `example.invalid` 仅用于工程验证，未冒充已核实技术资料。

### 3.2 原操作身份与状态

写请求使用当前账号、请求UUID、原目标及规范化输入固定身份。提交分别记原始 `input_document_id`（创建时为空）和实际生成的资料根，不混用“创建”与“向既有根追加”。同一账号的请求身份跨提交/审核种类比较，账号锁防止跨表身份并发复用；数据库另约束各表的账号/操作唯一、根/版本序号唯一、每版本至多一个审核决定。

同请求同输入返回原版本；同请求不同正文/原目标/种类或旧摘要返回409。其他请求再次审核已裁决版本返回409，不能覆盖已有决定。查询按原操作者及操作ID读取固定版本和该版本的审核事实，不查询“最新版本”拼装成功；提交原操作在后来审核后可显示该固定版本的当前审核事实。

状态为 `PENDING_REVIEW → APPROVED / REJECTED`，正文从提交起不可变，修改必须追加新版本。同步提交中是客户端等待事实，本项没有伪造持久异步 `PROCESSING` 任务。输入/权限/状态拒绝与数据库或回包不可核实明确分开；数据库异常保守返回503 `RESULT_UNKNOWN`，不宣告未执行。

### 3.3 短事务及来源公开能力

使用同一数据源的TransactionTemplate。锁顺序为当前维护账号行 → 知识根行；在锁内调用 `AccountWriteGuard.requireCurrent` 并重查当前凭证/角色、预期账号、版本摘要与已有决定。两个维护者的相反决定由共同根锁和唯一审核行串行裁决。创建根与首版本一起提交，审核决定一次提交；没有事务内外调、独立事务补偿或隐藏重试。

生产公开能力 `KnowledgeService.findApproved(versionId)` 以精确版本查询真实仓储，待审/拒绝返回空；批准返回原文、定位、适用条件、许可说明、摘要与审核时间。此能力仅证明审批门禁，后续消费者仍须判断条件及引用支持；不等于相似度检索、知识发布集合或评分依据充分。本项不新增任意读取私有数据的公开能力。

## 4. API与页面结果核实

前缀 `/api/maintenance/knowledge`，写请求包含CSRF、`X-Expected-Account-Id`、`X-Operation-Id`；成功响应均200、no-store，返回显式契约类型，不暴露仓储对象。

| 方法/路径 | 作用 |
| --- | --- |
| POST `/documents` | 创建根及待审版本；正文为固定知识输入 |
| POST `/documents/{root}/versions` | 追加待审不可变版本 |
| GET `/documents` | 维护者最小版本列表；当前一次返回所有版本，未实现大规模分页 |
| GET `/documents/{root}/versions/{version}` | 维护者核对指定版本 |
| POST `/documents/{root}/versions/{version}/review` | `digest/decision/reason`，决定为APPROVE或REJECT |
| GET `/operations/{operation}` | 当前维护者核实自己的原提交/审核 |

400 `INVALID_INPUT`；匿名401 `AUTHENTICATION_REQUIRED`；角色不足403；不存在/非本人原操作404 `RESOURCE_UNAVAILABLE`；409 `ACCOUNT_CHANGED`、`OPERATION_CONFLICT`、`KNOWLEDGE_STATE_CONFLICT`；503 `RESULT_UNKNOWN`。本项无供应商失败或自动重新生成。

Pinia保存当前固定操作及输入；提交中和未知时禁止冲突编辑/新请求，未知可查询原操作，内存仍保留输入时可重发同一UUID。不重建UUID猜测结果，不以404判定未受理。刷新仅在sessionStorage保存账号绑定的操作ID，正文、草稿、文件和凭据不落持久存储；刷新后可核实，不能无原输入重发。身份核实中清内存，同账号保留最小回执；匿名或切账号清回执，世代号拒绝旧账号响应覆盖。每次写/核实前读me，服务端仍独立执行资格复核。
