## 2. REF-S05-A/v0.1：volatile发布（正确回答）

**问题/固定前提**：共享对象已在启动两个线程前安全发布。初始`int value=0; volatile boolean ready=false;`，写线程仅执行`value=42; ready=true;`；读线程仅执行`if (ready) { consume(value); }`。没有其他写入。读线程进入分支时能否保证读到42？改成普通boolean能否保持保证？

**待评回答全文**：可以保证。value赋值在volatile写之前，读线程观察到ready为true后再读取value，通过volatile写读及程序顺序的传递关系，value的写对这次读取可见。普通boolean没有这条同步关系，不能保证相同结果。这里也不保证读线程多久能看到true。

**参考事实/替代表述**：需要明确“读到true”和前提中的唯一写入；给出value写→ready写→ready读→value读链，区分内存保证与时钟/调度。接受准确的发布/获取措辞；无需背诵规范英文。不同实例或存在后续value写入时必须重分析。

**错误/阻断点**：以线程先启动或一次实验代替关系；认为volatile使所有复合操作原子；推断对端提交或收费事实。来源支持为J1，Java语义不证明网络事实。追溯TD-06/OP-02、CF-04、原ACC-07评分与引用要求，见统筹4.4及设计追溯。

## 3. REF-S06-A/v0.1：同锁保护名额（正确回答）

**S06组共同问题/前提**：单进程共享`AtomicInteger remaining=1`，两个线程执行`if (remaining.get()>0) { remaining.decrementAndGet(); admit(); }`。admit只代表本地准入记录、无远端副作用且不会抛错。能否保证只有一次准入且不为负？给出一种修正，并说明若显式锁获取失败/异常退出应如何处理。该问题同时固定用于第4节C类回答。

**待评回答全文**：不能。两个线程可能都先读到1，再分别减成0和负1并各准入一次。可用同一个显式锁把判断、扣减和本地准入共同保护起来，所有调用者都遵守这把锁。只有成功取得锁才进入受保护区，并在finally释放；tryLock失败就返回未准入，不能继续扣减或unlock。不应在这个临界区里增加远端调用。

**参考事实/替代表述**：复合检查和更新须有共同保护；接受在前提不变时通过CAS循环实现名额判定，但本地准入须恰好发生在成功扣减后且不能把不可重用副作用放进updateAndGet函数。J2支持显式锁配对，J3支持单次原子操作；不得推成数据库或跨进程完整幂等。

**错误/阻断点**：不同锁对象；未获取仍准入；异常漏释放；宣称原子类自动把组合原子化；循环内部重复admit。追溯TD-06/OP-02及统筹4.4，规则仅讨论此本地问题，不替代项目TD-02账号→知识根锁。

## 4. REF-S06-C/v0.1：将单次原子性误当组合原子性（错误回答）

**问题/前提**：逐字使用第3节S06共同问题，不增加远端异常等条件。

**待评回答全文**：能保证。AtomicInteger的get和decrementAndGet都是线程安全的，所以把它们连起来就不会超卖，也不用加锁。即使两个线程先读到1，CAS也会让第二个线程不能再减。

**参考事实/替代表述**：沿用第3节反例。decrementAndGet不会自动检查“必须大于0”；单独get之后的条件不是一次原子准入决定。应明确修正整个组合，而不是仅增加volatile。J3为方法契约依据，具体交错是本案例从契约作出的推演，不声称运行过并发测试。

## 5. REF-S07-E/v0.1：有界排队与取消（简短正确回答）

**问题/前提**：Java21、固定两个工作线程、有界队列、拒绝策略AbortPolicy。任务可能向远端提交操作。`Future.get(100ms)`超时后，能否认定任务未执行、远端未收费？如何处理队列饱和及取消？

**待评回答全文**：不能，get超时只表示等结果超时。队列满且线程已到上限时AbortPolicy拒绝提交，应明确告诉调用方未被这次提交接受。对已接受任务可尝试cancel(true)，但中断不保证执行体或远端停止；应核实原操作结果，不能直接重发或把费用记零。

**参考事实/替代表述**：J4中线程池说明支持拒绝条件，Future区分等待与取消，ExecutorService说明终止是协作性过程。拒绝的是本次提交，不覆盖此前已接受操作；远端结算/结果需另有供应商证据，Java文档只支持不能从本地状态推定。接受不使用API名但正确区分的表达。

**错误/阻断点**：超时或cancel等于远端未执行；无界队列冒充有界；捕获拒绝后返回成功；盲目换ID重发。追溯TD-04/06、OP-02、CF-04；不据此宣布项目生成预算或外调收费已验证。
