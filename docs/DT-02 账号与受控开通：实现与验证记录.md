# DT-02 账号与受控开通：实现与验证记录

日期：2026-10-28｜状态：**两项 P2 修复已完成独立复审，当前版本未发现新的可复现代码缺陷；部分验证证据待补。登录、私有资源隔离及产品验收未完成**。

## 范围与确认规则

本任务只实现 M-01 的账号读取、试用账号受控开通、密码散列和不可变 `Actor`。对应 PRD-01、ACC-01-05 的开通适用部分、BR-01、开发计划 DT-02。未实现登录、退出、当前身份、密码重置、会话撤销、前端或私有资源读取，因此不关闭 ACC-01、FS-A、PF/VP。

本轮用户确认：登录名按原样区分大小写精确匹配，必须为3～64位ASCII字母、数字、`.`、`_`、`-`；初始密码由系统随机生成，通过受控线下渠道交付。没有公开注册或首次改密页面。试用账号只授予 `TRIAL_USER`；`KNOWLEDGE_MAINTAINER` 不附带读取用户私有资料的权限。

## 实现

- `backend/src/main/java/dev/interviewcoach/identity/`：账号与权限仓储、`Actor`、版本化密码编码、事务包裹的开通用例和受控命令。
- `PasswordHashes` 采用 Spring Security 的 `DelegatingPasswordEncoder`，标识 `{pbkdf2-sha256-v1}`；PBKDF2-HMAC-SHA256、16字节随机盐、310000次迭代、256位输出。参数依据 [Spring Security 密码存储说明](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html) 和 [Pbkdf2PasswordEncoder API](https://docs.spring.io/spring-security/reference/api/java/org/springframework/security/crypto/password/Pbkdf2PasswordEncoder.html)，于2026-10-28核对实际依赖接口。后续调参须采用新标识，保留旧标识验证能力。
- 开通用 `SecureRandom` 生成24字节随机值，编码为32位Base64URL初始密码；账号和唯一 `TRIAL_USER` 权限在同一本地事务写入。数据库已有唯一登录名约束；V1/V2迁移未修改。
- `scripts/Provision-TrialAccount.ps1` 只接受受控本地交互控制台；缺少控制台时入口先拒绝。密码仅在成功提交后于本地控制台显示一次，脚本不接受预设密码参数，不把凭证放进源码、命令行参数或应用日志。操作者须使用不记录终端转录的受控终端，再经批准的线下渠道交付。
- `bootstrap` 的默认网页拒绝边界保留；非网页开通命令不加载Servlet安全链。没有新增公开账号接口。

## 独立审核 P2 修复与复测（2026-10-28）

原“只接受交互控制台”不足以证明维护授权：修复前，本机项目根目录、`.env`、开通脚本和打包 JAR 继承了 `Authenticated Users` 的修改权限和 `Users` 的读取权限。另一个发现也成立：旧检查位于 `ApplicationRunner`，Spring 会先建立 DataSource 并执行 Flyway。此前“非交互拒绝、账号未创建”的测试只查账号行，不能证明迁移历史未改变。

现在 `InterviewCoachApplication.main` 在 Spring 应用上注册 `TrialAccountProvisioningPreflight`，于 `ApplicationEnvironmentPreparedEvent` 阶段检查 `local,provision`、非 Web 模式、交互控制台、登录名、当前 Windows 操作者对项目关键路径的所有权与 ACL。检查失败时，应用上下文和数据源尚未建立，Flyway 尚未启动。`ApplicationRunner` 再执行同一授权检查作为防御。检查拒绝共享读取或修改的 ACL；本机项目根 ACL 已收紧为当前项目所有者、Administrators、SYSTEM，关键子路径继承后均无其他允许条目。根 ACL 原 SDDL 保存在忽略目录 `.cache/dt02-root-acl-before.sddl`；`scripts/Protect-ProvisioningWorkspace.ps1` 用于新检出目录的一次性本地加固，已在带 `Users` 权限的合成目录验证，并在当前已加固目录验证重复执行。
