## 1. 授权、范围与实际实现

用户本轮明确采用现有JDK21、PG16、Flyway、独立app schema及Boot管理的Session JDBC，并授权迁移和隔离基础验证。没有登录、开通/重置、密码编码、前端业务或其他产品功能。

## 5. 可重复命令

```powershell
# 目录：项目根；Engine与本项目PG16服务须已就绪，已有.env不覆盖
& './scripts/Verify-Persistence.ps1'

# 目录：backend；默认构建只跑4项bootstrap测试，不连接开发库进行破坏性验证
& '../scripts/Use-LocalTools.ps1'
./mvnw.cmd '-Dmaven.repo.local=../.cache/maven-repository' -B -ntp verify

# 目录：backend；先检查端口可用，停止使用同一JAR的本次进程再构建
$env:SERVER_PORT='18080'
java -jar target/interview-coach-backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=local
# 新终端请求 http://127.0.0.1:18080/actuator/health；Ctrl+C停止本次应用
```

需要重复完整集成验证时使用脚本，它每次生成新库并为该次运行保留独立日志，不向.env写入测试目标。直接启用database-verification profile而未准备隔离库/环境变量会失败，不能静默连接开发库或跳过。
