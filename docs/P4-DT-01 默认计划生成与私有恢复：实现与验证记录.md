## 2. 实际业务闭环与固定契约

M-03新`plan`包唯一决定默认计划、工作稿、操作、尝试、候选及接收。M-02公开`MaterialPlanFacts`核本人归属、指定简历/JD、当前版本、原文定位与用户确认；M-06公开`PlanEvidenceFacts`复用已审核/适用/未停用的生产筛选规则。协调者不访问其他模块仓储。`MaterialDeletionParticipant`参加原M-02删除事务，无网络、无独立事务或事后补偿。

首片只实现默认生成、只读计划及恢复。工程输入必须明确确认受限范围；当前范围由一组technology/version/scenario/claimKey锁定，计划主题名等于该technology，默认8/MEDIUM，合成夹具为单一Java主题。此确定性约束不证明真实多主题规划或语义质量；调整、保存、确认与本人历史发现分别留给DT-02/03，不以名称匹配宣告个性化通过。

固定输入包括本人资料/JD版本、材料/受限覆盖/新计划意图、知识集合/configDigest和条件、本地生成配置`bailian-beijing-qwen3.8-flash-plan-json-v1-max4096`、query配置`qwen3.7-text-embedding-flash-query-1024-dense-local-contract-v1`及政策修订。Key不入快照；这些是可证明的本地契约，不声称供应商别名为不可变快照。模型输出只接受严格结构、固定8题/中等、合计、实际固定原文片段及允许的知识引用；未知字段、虚构经历/来源、非法数量等拒绝。

派发/恢复还比较首个输入修订中固定的生成、query及政策修订与当前适配契约。若不一致则PAUSED_LOCAL/CONFIGURATION_CHANGED，不提供手动外调或原候选接收资格；不能仅“存过配置”却在重启后使用新常量。恢复原契约后才可显式恢复同一预算，升级本身不授权原操作换模。

身份与重放：

| 身份 | 实际行为 |
| --- | --- |
| 创建操作＋工作稿 | owner/createOperation唯一；相同输入查原工作稿，异输入409；原请求与后续结果ID分开 |
| 工作稿唯一生成步骤 | 更换请求UUID返回该工作稿原generationOperation，不能重开预算；另有在途/未知操作时同资料根不能另开执行 |
| 输入修订 | 追加确认摘要或明确同配置知识重绑，保留旧修订与累计预算；资料更新使旧未完成操作失效 |
| attempt | QUERY/GENERATE独立编号、类别、代次、截止、派发意图及用量；意图与计次共同提交 |
| candidate | 每attempt至多一份，有64KiB正文上限；持久候选优先恢复原接收，API不返回原始候选 |
| 正式plan/revision | 原工作稿唯一结果，接收与操作成功、候选接收共同提交；用途固定ENGINEERING_ONLY |
| 人工恢复请求 | 保留全部owner/request回执，不只记最后一次；同身份异动作/输入409，旧恢复不会覆盖新序列 |

生成步骤初始1＋自动最多1＋手动最多2，总计≤4。外部未知不静默补AUTO；手动不附加自动。派发意图已提交但本进程未获提交确认时不按内存发请求；该槽不返还。query累计初始1＋人工最多2、无自动重试，成功向量优先复用。两类预算不互借，重启、输入修订、租约/代次变化不清零。

排队20秒独立，领取后60秒包括query、检索、组装、等待和候选保存；query≤10秒且≤剩余时间。短事务5秒，派发/准备/保存的`lock_timeout`限制到剩余截止，锁后重读数据库时刻。外部AI共用5许可，原知识索引仍保持单外调；HTTP结束即释放实际许可，再做本地处理。单活动应用执行者，至多5个本地计划上下文，不提供多副本执行承诺。

## 3. 锁、恢复、费用及删除

固定顺序为账号→本人资料根→知识根按UUID排序→工作稿。人工重绑先锁旧/新知识根并集；等待账号锁后重新取得最新固定绑定，防止按领取旧快照锁错根。所有写入在锁内核当前资格、归属、版本、状态、代次及删除；用户请求额外比较观察到的凭证代次。外调在事务外。

| 故障/状态 | 核实与恢复 |
| --- | --- |
| 派发意图提交确认丢失 | 查原意图和结果；当前进程明确未发送时暂停DISPATCH_NOT_SENT；跨重启不能推断远端未执行 |
| 候选提交确认丢失 | 查原candidate，不再外调；显式ACCEPT接收原正文及身份 |
| 正式计划提交确认丢失 | 先查唯一正式结果；保持SUCCEEDED，不重接、不新增计划 |
| 接收及暂停登记失败 | 本执行者保留待核身份，仅重试核实/登记；未核实前不自动接收或外调。重启凡发现未接收候选均等待人工恢复 |
| EXTERNAL_UNKNOWN | 等待逐次费用确认；再次调用使用剩余手动槽，不以本地超时、断连或重启推定未执行/不收费 |
| 已收到但过期的响应 | FENCED/LATE_RESPONSE，与外部是否执行未知分开；拒绝正文，保留可核实回执，再调用同样要求费用确认 |
| 停用/知识不足 | BLOCKED_KNOWLEDGE，不以模型记忆补齐；可显式选择同条件同config的新审核集合，追加修订、清旧证据/候选，原查询向量与累计预算保留 |

已核实requestId/Token在独立短事务补原attempt，和候选是否合法分开；原已知字段不被后续未知覆盖，账单未知始终`cost_unknown=true`，不填零。未知登记本身失败时，后续核实仍保留EXTERNAL_UNKNOWN及费用确认要求，不能退化成普通本地暂停绕过确认。

M-02删除屏障、M-03操作代次失效和PLAN_PRIVATE_GRAPH清理清单同事务。清理覆盖工作稿输入、query向量、证据/提示词、输入修订JSON、全部候选与正式计划正文，以及M-02内容核对JSON；保留必要ID/计数/摘要作去重和核查。删除后原查询404，晚到只补无正文用量，不写回私有正文；B用户和公共知识不随A删除。

完成汇总核全部PENDING目标，不只PRIVATE_FILE。新图清理失败回滚后独立记失败/轮转时点，其他目标可继续；不撤销屏障、不重置原24小时时刻。长期备份、独立最新删除账本和恢复开放门禁仍属原开放项，不将本系统在线删除承诺扩展到供应商。

| 方法/地址 | 行为 |

| POST `/api/plan-workspaces` | 明确本人固定版本、范围和新计划意图，创建/重放工作稿 |
| POST `/api/plan-workspaces/{id}/generation` | 受理工作稿唯一生成步骤，202后查原操作 |
| GET `/api/plan-operations/{request}?kind=CREATE_WORKSPACE/GENERATE_PLAN/RESUME` | 按原请求种类找原结果，不读“最新”代替 |
| GET `/api/plan-workspaces/{id}`、`/api/plans/{id}` | 受保护原工作稿/正式结果 |
| POST `/api/plan-operations/{operation}/resume` | ACCEPT、RETRY、CONFIRM_INPUT及可选明确知识重绑；新恢复请求身份单列 |

沿用Session/CSRF、`X-Expected-Account-Id`与`X-Operation-Id`，no-store。400格式/输入、401会话/凭证、403权限/CSRF、404他人/删除/不存在、409固定输入/恢复冲突、503服务未开或数据库RESULT_UNKNOWN。客户端503/404不推断未受理。

`/app/plans`使用统一请求层/Pinia；me/CSRF通过、真正POST前才存sessionStorage最小回执(owner/operation/kind/workspace/resumeId)。不存私有正文、向量、候选或凭据。刷新/焦点只核实，不自动生成；身份不明隐藏正文，切账号清回执，旧epoch响应忽略。原账号可用受保护的原操作链接恢复；权威删除回执核实后清展示和回执。恢复按钮由服务端资格投影控制；引用只允许HTTP(S)，模型文本按纯文本显示。页面未提供假“开始”或DT-02调整确认。

默认`interview.plan.proof-enabled=false`，没有真实生成/私有query百炼接线。启用工程HTTP适配须同时满足local＋plan-verification、实际库名`p4dt01_verify_<16hex>`、同名环境标记、数据库注释`p4-plan-isolation-v1`、生产embedding=false、JDK三项启动属性及严格`http://127.0.0.1:端口`无额外路径/凭证。不从请求指定供应商，不读取Key。仅合成资料和标记合成知识能执行，正式结果固定ENGINEERING_ONLY，M-06维护探测仍runtimeReady=false。

本机HTTP故障适配只替换外部query/生成响应；账号、M-02/M-03/M-06、PG事务及候选接收均为生产能力。它不证明百炼query真实参数、HTTPS/HTTP2传输、模型可用性或收费；既有embedding的HTTP2证据不充当新生成适配证据。
