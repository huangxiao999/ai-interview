## 2. 生产规则与数据契约

M-03 `PlanRevisionService`拥有调整、保存、确认及原结果核实。M-02 `MaterialPlanFacts`复核本人固定简历/JD和删除屏障；M-06 `PlanEvidenceFacts.revisionCoverage`锁固定知识根并给审核主题目录。入口不执行规则，不跨模块使用仓储。

保存输入固定expectedRevisionId和完整主题列表。每主题包含稳定topicId、从1连续的order、固定coverage、正整数questionCount、BASIC/MEDIUM/ADVANCED、安排原因和固定简历/JD的非空原文引文。服务端使用审核目录的主题名及证据chunk身份，不信任客户端name/evidenceRefs/totalQuestions；主题身份/coverage不得重复，题量严格拒小数、字符串、溢出、0、负数，计算合计5～15。目录证明工程适用条件和来源关联，不能自动证明安排原因语义正确或个性化优质。

保存新增不可变修订，使用expectedRevisionId更新当前指针；确认新增指向某一确定修订的事实，不修改正文。相同修订不同确认请求复用同一确认事实。确认后可以另存新修订，新修订未确认，旧确认和旧正文保留。所有修订始终追加，不提供原位更新正文的生产API；未来M-04已引用版本仍须按原版本读取，开始/引用资格的真实竞争留待P5，不造假场次表证明。

原生成结果的planId/revisionId和payload保持原义，`GET /api/plans/{id}`仍返回首次生成结果；当前编辑结果通过独立修订接口读取。保存或确认请求同owner/operation及同规范化输入重放原修订，同身份不同kind/输入/plan拒409；后续其他窗口有新修订，不把原回执改指最新结果。

### 2.1 API

所有响应no-store，沿用Session/CSRF及X-Expected-Account-Id、X-Operation-Id，写入核当前凭证代次。

| 方法与路径 | 输入/可观察结果 |
| --- | --- |
| GET `/api/plans/{id}/revisions/current` | 本人当前修订、确认事实、当前可编辑/可确认资格和审核主题目录 |
| GET `/api/plans/{id}/revisions/{revision}` | 本人该历史修订，不用最新版替换 |
| POST `/api/plans/{id}/revisions` | expectedRevisionId、topics；201新修订或原保存结果 |
| POST `/api/plans/{id}/confirmations` | expectedRevisionId；200绑定该修订的确认事实 |
| GET `/api/plan-revision-operations/{operation}` | 原保存/确认接收的修订；404只表示当前不可查，不能单独推定未受理 |

非法分配400，未登录401，无权限/CSRF403，非本人/删除/不可访问404，CAS/资料换版/知识不足/操作冲突409，数据库事务或提交确认未知503。未知先查原操作，不自动重复POST；资料换版可读历史，拒绝新保存和确认。知识停用/冲突拒新使用，历史修订不冒充当前可确认事实。

### 2.2 事务、删除及费用

账号→资料根→按固定顺序的知识根→工作稿；短事务内重查凭证、归属、版本、删除、工作稿及expectedRevision。修订正文、当前指针、原请求回执共同提交；确认事实与回执共同提交。原操作查询也经过本人及删除资格核实。保存/确认没有外调或执行租约，不新建后台任务、预算或有界池。

V13仅追加`plan_revision`、`plan_revision_confirmation`、`plan_revision_request`及当前指针；旧计划按原revisionId回填第1修订，已清理的null正文仍为null。V1～V12及旧manifest不修改。保存和确认回执只留去重身份/摘要，不保存另一份私有正文。

新增payload进入已有PLAN_PRIVATE_GRAPH清理，删除受理在账号/资料锁下失效原工作稿，后续保存、确认及原回执读回均拒绝；清理新增全部修订payload后才允许该图完成登记。删除影响DTO与页面新增planRevisionCount，不仅核PRIVATE_FILE；保留原删除时刻/期限，不清其他用户/公共知识。保存先完成则删除覆盖新增修订，删除先完成则拒新写。迟到页面响应在卸载/切账号时失效，不能恢复正文。

调整不调用query/生成，不改四次预算、不产生场次、日权益、暂占或扣次；费用未知/原生成恢复规则不变。真实调用、费率、账号与质量证据继续单独登记。

## 3. 页面恢复

统一API/Pinia提供审核主题选择、增删/排序、题量/难度及依据编辑。草稿只在内存；显示未保存、保存未确认、已确认、历史/当前及工程用途。离开未保存草稿需明确确认，刷新提示可能丢草稿。

保存/确认在本人身份和CSRF预检后、实际POST前，仅存owner/plan/operation/kind；不存正文、候选、向量或安全凭据。结果未知时禁保存/确认和“准备另一份计划”，刷新核实原操作；404或读回故障不抹回执。已核实原回执后可另行查询当前修订，不能以当前指针猜原请求结果。CAS409保留草稿及其旧expectedRevision，查询当前不覆盖草稿，必须明确放弃并载入才能按新基线编辑。本窗口存在其他计划未核实回执时禁止用新目标覆盖它，先返回原页面核实；不扩展DT-03历史列表。

匿名/切账号清对应私有状态，编辑器因删除/身份核实卸载即失效在途响应。资料换版后的新计划出口沿用DT-01，不将旧修订草稿混入新目标。
